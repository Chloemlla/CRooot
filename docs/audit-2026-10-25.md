# SIGSYS 双端修复清单（2026-10-25）

触发：Project-Lumen `40f61ffc`，vivo V2426A / Android 16 / arm64，report `46e765d534fb`，`:virtualization_probe` 因 syscall 142 被 seccomp 拦截。Linux asm-generic/unistd.h 定义 `__NR_reboot=142`，不是孤立进程回收原因码。

## CR-S01：预期 seccomp 拒绝以原生崩溃结束

- 文件：`sdk/src/main/cpp/duckdetector/nativeroot/probes/ksu_supercall_probe.cpp:81-138`、`sdk/src/main/cpp/duckdetector/virtualization/honeypot_traps.cpp:398-705`，以及 `app/src/main/cpp` 对应副本。
- 类型：探针失败路径 / 原生信号处理。
- 症状：KernelSU reboot-magic 与 virtualization openat2 探针在 fork 子进程内执行；Android seccomp 的 SIGSYS 默认死亡路径会生成 tombstone。子进程继承宿主信号处置，没有把预期限制转换为结构化受限结果。
- 改法：只在 fork 子进程安装 async-signal-safe SIGSYS 退出处理，使用专用正常退出码传达受限；安装失败时不执行探针。父进程识别受限退出及 SIGSYS，保留 denied/disabled 标志，不将受限判为 clean/root。不得放宽或绕过 seccomp，不在宿主进程覆盖 SIGSYS handler。对 waitpid 的 EINTR 重试；虚拟化 pipe 先读后 wait，避免 payload 大于 pipe 容量时相互等待。
- 验证：CI 的 SDK 四 ABI 构建、lint、JVM 单测；新增 CI 原生子进程回归（实际 seccomp trap、父进程信号处置不变、正常分支）。真机复验待设备接入。
- 状态：已修，代码提交 `64c4124`；SDK CI [40148892450](https://github.com/Chloemlla/CRooot/actions/runs/40148892450) 成功。

## CR-S02：门面允许 detector 辅助进程再启动扫描

- 文件：`sdk/src/main/java/com/chloemlla/crooot/CRoootSdk.kt:218-222`。
- 类型：多进程递归 / 生命周期边界。
- 症状：SDK AAR 启动 `:virtualization_probe` / `:zygisk_fd_detector` 等服务时也会执行宿主 Application；宿主若自动扫描，辅助进程会再次启动所有检测器。Project-Lumen 当前即存在此路径。
- 改法：在 scan 的检测器创建之前拒绝 detector-owned 辅助进程和 isolated UID 扫描，抛出明确异常，不返回干净结果；保持合法宿主自定义进程可用。用纯函数回归测试钉住进程/UID 边界。
- 状态：已修，代码提交 `64c4124`；SDK CI [40148892450](https://github.com/Chloemlla/CRooot/actions/runs/40148892450) 成功。
